Diagnosis And Fix Trail

Original failure

旧 run 在 episode 120 仍正常：episode_return=+37.6835、priority=P3(cost)、loss_mean=0.3385、m1=0.8727。episode 121 是 anchor 后第一个 sampled-policy episode，Rescale 仍报告 any_invalid=False，但 model probe 进入 loss_mean=100.0000、m1=0.3164、priority=P1(acc)。这说明 optimizer-valid 不等于 model-safe。

Implemented source fixes

  • c937054 - Stabilize sequential RL safe curriculum: post-anchor near-baseline masks, PPO mask replay, absolute episode schedules.
  • e1a93ad - Wait for server RL before monitoring: SERVER_COMMAND waits for the background launcher pid before Step 5.
  • 1eaa6c3 - Relax monitor for stochastic reward dips while still failing P1/loss-cap anomalies.
  • 35b7daa - Guard sequential accuracy threshold for probe noise: subtract one 1/probe_size sample quantum from the noisy baseline threshold.
  • 66968d5 - Tolerate server pull timeout in command: allows current synced HEAD when GitHub HTTPS times out.

Second-order issue found during validation

第一版 safe curriculum 消除了 loss_mean=100，但 baseline anchor 内仍偶发 false P1(acc)：256 probe size 下一个样本就是约 1/256=0.0039，而原阈值只给 0.005 tolerance，导致正常 baseline 抖动可能被误判为精度失败。最终修复是在 noisy baseline threshold 上额外扣除一个 probe quantum；这不会放过 episode 121 那种 m1≈0.3164 的真实崩塌。
