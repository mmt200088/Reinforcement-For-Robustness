BLB Stage 2 RL Reward 设置报告

本报告按当前代码总结 BLB Stage 2 顺序 RL 的 reward 计算。核心结论： reward 是 hard-priority gate + clipped shaping 的结构，准确率优先，稳定性第二，成本最后。 成本只在准确率通过后才生效，不能补偿准确率失败或 optimizer invalid。

终局主 rewardtier + shaping
优先级P1 > P2 > P3
shaping clip[-5, +5]
合格 tier+40

1. 当前 reward 分两层

层级 发生位置 作用 权重规模
顺序 step dense reward blb_stage2_rl/sequential_env.py 每个 block step 每一步先调用 Rescale_optimizer，给一点成本 shaping 或 invalid penalty，让 PPO 在完整 episode 结束前获得局部信号。 很小。默认 cost_shaping_coeff=0.05，invalid_penalty=1.0，fusion_shaping_coeff=0.0。
终局 terminal reward blb_stage2_rl/env.py 调 compute_reward 完整 577-wide action 装入模型后，跑多次推理得到准确率和 loss_std，再按 hard-priority 公式算 reward。 主信号。通过准确率得 +20，再通过稳定性得 +20，shaping 只在 [-5,+5] 内微调。

因此日志中的 episode_return 约等于： 

episode_return = sum(per_step_reward over 59 sequential steps) + terminal_reward

目前 MRPC/BERT-base 顺序 horizon 是 59 步。通常 terminal_reward 贡献最大， step dense reward 只会让最终回报上下移动几个点以内。

2. 终局 reward 精确公式

当前公式在 blb_stage2_rl/reward.py::compute_reward 中实现：

margin_acc = (metric1_mean - acc_threshold)
             / max(abs(baseline_metric1 - acc_threshold), 0.01)

bits_drop   = baseline.total_bits_sum - opt_signals.total_bits_sum
fusion_drop = baseline.total_fusion_count - opt_signals.total_fusion_count
k_drop      = baseline.avg_k - action_avg_k

bits_score   = bits_drop   / max(abs(baseline.typical_bits_drop), 1.0)
fusion_score = fusion_drop / max(abs(baseline.typical_fusion_count), 1.0)
k_score      = k_drop      / max(abs(baseline.typical_k_drop), 1.0)

cost_score_raw = cost_weight * (bits_score + fusion_score + k_score) / 3

stab_excess       = max(0, loss_std - stab_threshold)
stability_penalty = -lambda_stab * stab_excess

metric_ok = (metric1_mean >= acc_threshold) and not any_invalid
stab_ok   = (stab_excess == 0)

shaping_raw = margin_acc
              - invalid_penalty if invalid else 0
              + cost_score_raw if metric_ok else 0
              + stability_penalty if metric_ok else 0

shaping_clipped = clip(shaping_raw, -5, +5)

tier_bonus = 0
if metric_ok:
    tier_bonus += 20
    if stab_ok:
        tier_bonus += 20

terminal_reward = shaping_clipped + tier_bonus

3. 默认权重和大致占比

项目 默认值 含义 在总 reward 中的影响
准确率 gate metric_ok 通过后 +20 metric1_mean >= acc_threshold 且没有 any_invalid。 最高优先级。不过关时不会给准确率 tier，也不会启用 cost/stability shaping。
稳定性 gate stab_ok 通过后再 +20 loss_std <= stab_threshold。 第二优先级。通过后 reward 从约 15-25 跳到约 35-45。
准确率 margin 无固定上限，进入 clip 用当前准确率相对阈值的距离做连续 shaping。 和 cost/stability penalty 一起被 clip 到 [-5,+5]。
稳定性 penalty lambda_stab=5.0 -5.0 * max(0, loss_std - stab_threshold)。 只在准确率通过后生效；最终仍受 shaping clip 限制。
optimizer invalid penalty -5.0 any_invalid 时一次性加入 shaping。 足以把 shaping 压到下限附近，并且 invalid 会让 metric_ok=false。
cost score cost_weight=1.0 bits、fusion、truncation K 三项归一化后平均。 最低优先级。只在准确率通过后参与，且被 [-5,+5] clip。
整体比例直觉： 一个完全合格的 action 基础 tier 是 +40，shaping 最多只能贡献 +5 或 -5。 所以终局 reward 的主排序先看是否进入 +20/+40 tier，cost 只是合格候选之间的微调。 若把合格区间看成 35 到 45，cost 在极端情况下最多影响约 10 到 12.5 个百分点的终局分数区间； 正常情况下通常更小，因为 shaping 里还包含 accuracy margin 和 stability penalty。

4. 优先级逻辑

priority 触发条件 reward 区间直觉 解释
P1(acc) metric1_mean < acc_threshold 通常接近 [-5, +5]，实际常为负 准确率不达标，不能用 cost 弥补。当前监控把大量或连续 P1 当作训练崩塌风险。
P2(stab) 准确率达标，但 loss_std > stab_threshold 约 [15, 25] 模型精度还可接受，但稳定性没通过，因此只有 metric tier +20，没有 stability tier +20。
P3(cost) 准确率和稳定性都达标 约 [35, 45] 此时 cost 才作为低优先级优化目标参与候选排序。

注意一个实现细节：any_invalid 会让 metric_ok=false，并加 -5 invalid shaping penalty。当前 priority 标签本身只按 accuracy violation 和 stability excess 标注，所以 invalid 是单独通过 RewardBreakdown.invalid 和 invalid_term 体现。

5. cost 内部比例：total bits、fusion_count、truncation K

终局 cost 的当前比例是三项等权平均，但每项先按 baseline 校准出来的 typical scale 归一化：

cost 子项 公式 终局 cost 内部权重 方向
total bits (baseline_bits - current_bits) / typical_bits_drop 约 1/3 bits 越少越好，正分越高。
fusion_count (baseline_fusion_count - current_fusion_count) / typical_fusion_count 约 1/3 相对 baseline fusion 越少越好。若 baseline fusion 为 0，出现 fusion 通常给负分。
truncation K (baseline_avg_k - action_avg_k) / typical_k_drop 约 1/3 平均 K 越低，MPC truncation 成本越低，正分越高。 
cost_score_raw = (bits_score + fusion_score + k_score) / 3

这里的 typical_bits_drop、typical_fusion_count、typical_k_drop 来自训练启动时的 random action 校准。这样做的目的不是让 bits/fusion/K 使用同一个物理单位， 而是把三种不同量纲转换成可比较的 dimensionless 分数。

6. 顺序 step dense reward 的成本比例

除了终局 reward，当前顺序 RL 每个 block step 还会给一个小额 dense reward： 

if invalid:
    per_step_reward -= 1.0
else:
    cost_ratio = this_block_total_bits / baseline_block_total_bits
    per_step_reward -= 0.05 * (cost_ratio - 1.0)
    per_step_reward -= 0.0 * fusion_count
dense 子项 当前权重 比例解释
block total bits ratio 0.05 dense cost shaping 的主要来源，约等于 dense cost 的 100%。
block fusion_count 0.0 当前不直接参与 per-step dense reward。
truncation K 无直接 dense 项 K 只在终局 cost 的 k_score 中参与。
invalid step -1.0 比常见 dense cost 大很多，用于快速学会避开 invalid block。

7. 当前 MRPC preset 的阈值来源

参数 当前 preset 运行时解释
--stage2-limit-tolerance 0.005 用于从 noisy baseline accuracy 推出 acc_threshold，大意是允许约 0.5 个百分点的 metric1 下降。
--stage2-stability-tolerance 0.005 用于从 noisy baseline loss_std 推出 stab_threshold，公式近似 baseline_loss_std * 1.005，并至少为 0.01。
--stage2-calibrate-baseline-samples 8 用于估计 cost normalization 的 typical drop。
--stage2-probe-size 由 launcher/env 传入 终局 reward 的 metric 来自多 trial probe。我们之前已经把双卡并行用于这些 probe 以加速 reward 采样。

8. 对训练曲线的含义

  • 正常合格 episode 应主要落在 P3(cost)，终局 reward 大约 35 到 45。
  • 偶发 P1 或 loss_mean=100 cap 不是自动失败，但如果连续或在 rolling window 内大量出现，就说明策略进入不安全动作区域。
  • cost 的改进不应该以牺牲准确率为代价，因为 accuracy gate 没通过时 cost score 完全不生效。
  • fusion_count 在终局 cost 中仍占约 1/3，但在 per-step dense reward 中当前权重为 0。
  • truncation K 在终局 cost 中占约 1/3，但没有单独的 per-step dense 项。
