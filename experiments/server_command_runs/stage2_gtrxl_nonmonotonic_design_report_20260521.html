1. 旧方案的问题

问题表现这次怎么处理
MLP policy/critic 表达力偏弱 上一版 10k 训练长期 reward 变化小，frontier 后期扩展慢，dominated/duplicate 样本占比高。 换成 v2-scale GTrXL token model，让策略能利用 59-step 历史、block/layer 位置、前序动作和 optimizer signals。
baseline prior 容易锁死 强 warmstart 对安全启动有帮助，但长期看会把策略压在 baseline 附近。 把永久 actor bias 改成外部衰减 logit prior，并把 baseline_prior_scale 写入 transition 以保证 PPO replay 一致。
探索方向曾隐含“越低越好” SF 与精度/稳定性不单调；低 SF 可能失败，高/横向 move 也可能通过 optimizer 带来更好 cost。 改成 non-monotonic empirical proposal：SF/K move 只是 proposal，真实边界方向由 F1 metrics、stability、Rescale_optimizer cost 和 Pareto event 决定。
PPO value/advantage 稳定性不足 长 run 中 value loss 可能压过 policy signal，或 PPO epoch 更新过猛。 加入 return normalization、clipped Huber value loss、MAD advantage clipping、approx KL early stop、adaptive LR 和 entropy recovery。

2. 从 noise_rl_module_v2.py 借鉴的点

这次没有照搬 v2，因为当前 Stage-2 的动作空间是 59-step sequential + 最多 13 slot/head + 577-wide full action，和旧 v2 的动作数不同。借鉴的是结构原则：

  • 使用更强的序列 trunk，而不是浅层 MLP。
  • critic 保持单 value head，避免引入额外 mean auxiliary head 后改变 value 语义。
  • actor logits 初始化保持很小，让 baseline prior 在早期可控。
  • 训练过程更重视 KL、value loss 和 entropy 的可监控性。

3. 新 policy / critic 设计

模块新实现优点代价
Token input step/layer/block embedding + previous action embedding + previous optimizer signals + static features + current-step marker 策略能看见“之前哪些 block 已经做了什么”和 optimizer 反馈。 比 MLP 慢，checkpoint 与旧结构不兼容。
GTrXL trunk d_model=256, n_heads=8, n_layers=4, d_ff=512, dropout=0.1 表达力接近先代 v2 成功路径，适合 horizon=59 的序列决策。 需要 fresh run，短 smoke 不能代表长期效果。
Actor 最多 13 个 per-slot heads，每个 head 输出最多 6 个 level logits；继续使用 slot/action-level mask。 保留当前 action-space mask 合约；每个 slot 头可以学到自己的局部分布。 每个 slot 的 entropy/lock-in 要单独监控。
Critic Linear(256,64) -> Tanh -> Linear(64,1) value 语义简单，PPO 回放与 checkpoint 更清楚。 没有辅助任务，value 学习完全依赖 reward/GAE。

4. Non-monotonic cost-boundary exploration

“向边界移动”被重新定义为 cost-boundary move，不是 raw SF downward move。候选如果降低 SF 但 P1/P2/loss-cap/stability violation，就进入失败统计和 cooldown；候选如果提高或保持某些 SF，却通过 optimizer 带来更多 fusion、更低 K 或更少 total bits，并且通过 P3 硬约束，就可以进入 frontier。

  • 默认 forced baseline anchor：60 episodes。
  • Baseline prior：1.2 anchor；episode 60-600 从 1.0 衰减到 0.45；episode 600-2000 衰减到 0.15；之后保持 0.15。
  • Radius1 mask：SF-like slot 在 base action 两侧双向局部扰动；K 用 K_LEVELS 的 truncation-bit 距离。
  • Base action source：baseline 或近期 Pareto frontier seed，而不是永远 baseline。
  • Empirical stats：每个 offset 记录 P3 成功、P1/P2、loss cap、stability violation、invalid、frontier/member/dominated/duplicate、平均 cost-vector 变化。
  • Guarded radius2：只从至少 3 次 P3 成功且 0 失败的 offset 里采样；任何硬失败触发 cooldown。

5. PPO 稳定器

稳定器作用诊断字段
Running return normalization把 value loss 尺度压住，减少 value 梯度盖过 policy 梯度。return_mean, return_std
Clipped Huber value loss避免 value 预测一步跳太大。value_loss
MAD advantage clipping削弱异常 reward 尖刺对 PPO batch 的影响。间接反映在 policy loss / KL
Approx KL early stop防止一次 PPO update 把 policy 推离采样分布。approx_kl, kl_early_stop
Adaptive LRKL 过大降 LR，KL 过小适度升 LR。lr, lr_scale
Per-slot entropy recovery某些 slot 熵低于 floor 时补探索压力，减少早期锁死。entropy_recovery_delta
