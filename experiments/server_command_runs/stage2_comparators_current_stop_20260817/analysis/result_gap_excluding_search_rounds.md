# Stage-2 三种对比算法结果偏差分析（排除搜索轮数）

## 结论

排除搜索轮数、评估次数和提前停止后，结果偏差的首要原因仍不是精度或稳定性阈值写错，而是：

1. 在线可行判定较宽松；
2. 候选排序首先追求资源收益；
3. 在线评估与严格评估不是同一统计强度；
4. 严格验证结果没有反馈回搜索过程。

这四项叠加后，算法会偏向“Fusion 更多、精度更低、资源收益更高”的配置。它们在在线 probe 上可能被判为可行，但在完整验证集上容易越过精度边界。

## 不是约束参数写错

三种算法与 RL 使用相同的核心约束：

- Loss 上限：`baseline_loss × 1.001`；
- Accuracy/F1 下限：`baseline_metric × 0.999`；
- 三项标准差上限：`baseline_std × 2.0`；
- 相同模型、MRPC 数据、batch size、Fusion mapping、H/M/L K 配置和严格验证 Bank A/B/C。

BO-RF 的严格候选通过了三项稳定性约束，却同时违反 Loss、Accuracy 和 F1 的均值约束。因此 BO-RF 的主要失败不是稳定性约束，而是配置过于激进造成的精度下降。

## 主要原因

### 1. 资源优先排序把搜索推向过度激进配置

候选一旦在线判定为可行，排序首先比较资源分数，约束安全余量只用于后续同分比较。

| 方法 | 资源分数 | Fusion 层数 | H/M/L |
| --- | ---: | ---: | ---: |
| RL | 0.604 | 6 | 2/3/7 |
| BO-RF | 0.833 | 10 | 1/2/9 |
| Greedy | 0.979 | 12 | 0/1/11 |
| COINN-GA | 0.938 | 12 | 0/3/9 |

三个对比算法找到的配置都明显比 RL 更激进。它们优化的不是最高 Accuracy，而是“满足约束前提下尽量节省资源”；在线门禁一旦产生误判，资源优先排序就会放大误判。

### 2. 在线“可行”不等于原始指标满足约束

在线阶段使用 3 次 trial 和 bootstrap 通过概率，门槛为 `0.5`。代码以“通过概率减门槛”判断在线可行，而不是强制要求当前点估计满足六项约束。

实际例子：

- Greedy Loss std：`0.007271 > 0.006549`，仍被标记为在线可行；
- GA Accuracy std：`0.007813 > 0.007509`；
- GA F1 std：`0.008372 > 0.007604`。

所以数值阈值本身正确，但在线执行方式较宽松。这是当前最重要的结构性原因。

### 3. 在线 probe 与严格验证存在统计落差

在线阶段使用固定 256 个样本和 3 次 trial；严格阶段使用完整 408 个样本，并按 Bank A/B/C 累计到 45 次 trial。

搜索长期针对同一个小 probe 选择候选，会产生 probe 过拟合和“幸运候选”效应。即使继续增加搜索轮数，这种偏差也不会自动消失，反而可能因为比较了更多带噪候选而更明显。

Greedy 和 GA 当前只有在线结果，因此其数值不能直接与 RL 的 408 样本、45 trials 严格结果比较。

### 4. 严格验证没有反馈回搜索

严格验证只在搜索结束后检查在线排名靠前的 5 个候选。若这 5 个候选失败，BO、Greedy 和 GA 不会根据失败原因继续寻找更保守的配置。

因此，即使搜索轮数相同，只要仍采用“搜索结束后才严格验证”的流程，就可能反复选中同一类高资源、低安全余量候选。

### 5. BO-RF 的代理目标与最终严格目标存在差异

BO-RF 的随机森林学习的是在线 bootstrap 约束余量，采集函数优化的是“在线可行概率 × 资源改进”，而不是完整验证集上的严格可行性。

因此 BO-RF 可以很好地拟合在线门禁，却仍然无法可靠预测严格验证结果。这是 BO-RF 特有的额外原因。

### 6. BO-RF 的 Stage-1 起点较弱，但不是主因

BO-RF Stage-1 相比 RL/Greedy/GA：

- Accuracy 低约 0.245 个百分点；
- Weighted F1 低约 0.203 个百分点。

这会贡献部分差距，但 BO-RF 使用自己的 Stage-1 baseline 后，严格门槛也相应更宽松。它在更宽松门槛下仍失败，因此 Stage-1 只能解释小部分结果。

## 最终判断

按影响程度排序：

1. **在线概率门较宽松，且替代了原始点约束；**
2. **在线可行后资源分数优先，导致配置过度激进；**
3. **256×3 在线评估与 408×45 严格评估存在统计落差；**
4. **严格失败不反馈给搜索，只验证在线 top-5；**
5. **BO-RF 代理目标与严格目标不完全一致；**
6. **BO-RF Stage-1 起点较弱。**

没有证据表明模型、数据集、Fusion mapping、K 配置或精度/稳定性阈值发生了接线错误。问题主要位于“在线筛选与最终严格目标之间的衔接”。

修改在线门槛、候选排序或严格反馈机制会改变搜索结果，属于科研协议修改，不是单纯运行效率优化；若只修改三个对比算法，也会破坏它们与现有 RL 的完全对齐。
