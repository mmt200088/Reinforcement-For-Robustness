# BLB orphan-slot audit — profile `mrpc`

Three-layer trace of every RL action slot through to a Rescale_optimizer graph node. Generated by `scripts/blb_orphan_slot_audit.py`. Static AST + JSON only (no torch needed).

**Layers**:
- L1 — `make_block{N}_default_config` in `function_handler.py` (slot kwarg → cfg attribute)
- L2 — `default_block{N}_cfg_to_delta` in `rescale_optimizer_bridge.py` (cfg attribute → delta_overrides key)
- L3 — `/Users/pengjunkai/Desktop/PPTI/Local/Reinforcement-For-Robustness/Rescale_optimizer/configs/mrpc/block*.json` (graph node names)

**Reading the tables**:
- *reaches optimizer = no* → action slot influences model noise install but is invisible to cost.
- *bridge driver = (none)* → graph node is NOT under RL control; optimizer uses graph defaults for it.
- Bridge orphans = bridge code sends a key that this graph doesn't have (real bug or stale name).

- **Block 5 degree-aware bridge orphans.** `default_block5_cfg_to_delta` only writes `ctct_gelu_x2` when `cfg.gelu_degree >= 2` and `ctct_gelu_x4` when `cfg.gelu_degree >= 4`. The AST extractor doesn't see these guards, so it lists them as orphans for `block5_n1` (no gelu_x*) and `block5_n2` (no gelu_x4). At runtime the bridge skips them for those graphs.
- **Block 2 Q/K SF tie.** Q and K share `ctpt_wq_wk` by BLB constraint. The bridge sends `cfg.wq_encode.scaling_factor` only; `wk_sf` action is decoded into model noise but ignored on the optimizer side. If the optimizer requires Q=K tied, `tied_group` enforcement should be in the registry.
- **`source` nodes appear as graph-only.** Each graph's `source` node (e.g. `gelu_out`, `inv_std`, `X`, `rot_softmax`, `x_mean`) is intentionally driven by `t_new[0]` from the cfg's `*_fresh` field, not by `delta_overrides`. The audit lists them as graph-only for clarity; they are NOT actually orphan.
- **Loop-generated keys** (`ctct_square_{k+1}` in block 3) come from a runtime loop over `cfg.degree`. The audit flags them as `loop` instead of mapping to a single static cfg field.
