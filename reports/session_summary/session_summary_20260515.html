1. 背景与本次目标

用户的几个递进诉求：

  1. 接口正确性：再次确认 RL ↔ Rescale_optimizer 接口无遗留 bug。
  2. 动作空间精简：原来每层 48 个槽位 × 12 层 = 577 维 MultiDiscrete，PPO 收敛困难，需要重新设计。
  3. 序列化决策：用户最终选择「逐 block 序列决策」——L0:B2→B3→B4→B5，L1:B1→B5，…，L11:B1→B5（首层无 block 1），horizon = 59。每步只决策一个 block；密集每步奖励 + 全历史状态 + first_input 并入 step 0。
  4. 默认化：把新方式做成 stage-2 RL 的默认路径，旧的单步 577 维路径暂时关闭（保留可选）。
  5. 可运行性：交付后代码能直接跑。

2. 第一轮：Q/K 绑定同步 bug + 修复

动作空间精简后 Block 2 的 Q 侧动作（wq_sf / q_mask{1,2}_sf）与 K 侧绑定（即 RL 只决策 K 侧，Q 侧字段在 cfg 上同步填入 K 侧值）。再过一遍接口时发现一个真实 bug：

路径读 / 写结果
apply_optimizer_output_to_cfg只重写 wk_encode / kt_mask{1,2}_encode（这三个在 GRAPH_NODE_TO_CFG_ATTR[2] 里）Q 侧 cfg 字段未被修改
function_handler.handler_block2:3410+3432装模型噪声时直接读 cfg.wq_encode / cfg.q_mask{1,2}_encodeQ 通道用 RL 旧 SF，K 通道用 optimizer 新 SF — Q/K 绑定不变量被静默打破

修复

在 rescale_optimizer_bridge.py 加 sync_block2_qk_binding(cfg)，并在 env.step 的 override 循环中 block_idx == 2 时调一次（同时也在新的序列 env 里用上）。

_BLOCK2_QK_BINDING_PAIRS = (
    ("wq_encode", "wk_encode"),
    ("q_mask1_encode", "kt_mask1_encode"),
    ("q_mask2_encode", "kt_mask2_encode"),
)

def sync_block2_qk_binding(cfg) -> List[CfgOverrideEntry]:
    """Mirror K-side encode SFs onto their bound Q-side counterparts."""
    overrides = []
    for q_name, k_name in _BLOCK2_QK_BINDING_PAIRS:
        q_point = getattr(cfg, q_name, None)
        k_point = getattr(cfg, k_name, None)
        if q_point is None or k_point is None: continue
        new_sf = int(getattr(k_point, "scaling_factor", 0))
        old_sf = int(getattr(q_point, "scaling_factor", 0))
        if old_sf == new_sf: continue
        q_point.scaling_factor = new_sf
        overrides.append(CfgOverrideEntry(
            cfg_attr=f"{q_name}.scaling_factor", graph_node=None,
            source="qk_binding_sync", old_value=old_sf, new_value=new_sf,
        ))
    return overrides

4-case 单元测试：Q 滞后 K → 3 处覆写；已同步 → no-op；缺字段 → 跳过；部分错配 → 只改错配字段。全过。

3. 第二轮：动作空间精简（48 槽/层）

之前一轮的工作。Block 1: 9→7，Block 2: 23→12（Q 侧 3 个槽并入 K 侧），Block 3: 8→7，Block 4: 17→12，Block 5: 16→10。每层 48 槽，12 层 + 1 first_input = 577 维。但即便如此，5^577 的搜索空间对 horizon=1 的 PPO 仍极不友好。

4. 第三轮：Per-block 序列决策设计

维度旧（single-shot）新（sequential per-block）
Episode 长度1 步59 步（L=12：4 + 11×5）
每步动作维度577 维 MultiDiscrete7-13 维 MultiDiscrete（按 block 切片）
GAE退化为 A = r − V(s)真正发挥作用（γ=0.99，λ=0.95）
Reward 信号仅 episode 末每步密集：ReplanSession 返回 (valid, total_bits, fusion_count) → invalid 重罚 / 有效则 cost shaping；末步追加完整 hard-priority reward
状态特征静态汇总静态 + 当前 (block, layer) + 之前所有 step 的动作 + 之前所有 step 的 optimizer 信号
first_input fresh动作向量末尾 1 个槽并入 step 0（L0-B2）的动作向量
层 0 处理block 1 槽存在但被禁用L0 没有 block 1 step（schedule 跳过）

5. 实现：3 个新模块 + 接入

5.1 blb_stage2_rl/action_space.py（增量）

函数 / 类作用
BlockStepSpec每步的完整规格：step_idx / layer_idx / block_idx / slot_dims / slot_field_names / slot_kinds / full_vec_offsets / includes_first_input / graph_key_suffix / terminal
step_schedule(num_layers, profile, attn_degree_per_layer, gelu_degree_per_layer)构造 horizon=59 的有序 schedule；graph_key_suffix 自动按 Stage-1 degree 解析（block3_exp_nX、block5_nX）
horizon_for_num_layers / step_schedule_max_dim常用查询（L=12 → horizon=59，max_step_dim=13）
splice_step_action_into_full_vec把单步动作切片写回 legacy 577 维 vec（terminal step 调 base.step 时需要完整 vec）
empty_full_action_vec零初始化 577 维 vec

5.2 blb_stage2_rl/sequential_env.py（新）

BLBStage2SequentialEnv 包装现有 BLBStage2Env，实现 horizon-N gym 接口：

  • reset()：清场（委托 base），rebuild schedule（按当前 Stage-1 degrees），初始化 _pending_full_vec。
  • step(per_step_action)：(1) splice 到 _pending_full_vec；(2) 解码该 (block, layer) 的 cfg；(3) 调用 单 graph ReplanSession 拿即时 cost 信号；(4) apply_optimizer_output_to_cfg + sync_block2_qk_binding；(5) 若 invalid → 大负奖励（可选 early-terminate）；(6) 若 valid → cost shaping = -coeff × (total_bits/baseline - 1)；(7) 末步把累积的 full vec 交给 base.step 做完整模型 forward + 完整 reward。
  • SequentialEnvConfig：invalid_penalty / cost_shaping_coeff / fusion_shaping_coeff / early_terminate_on_invalid。
  • 修复一个边界 bug：base.attn_degree / base.gelu_degree 当为单元素 ndarray 时，_rebuild_schedule 现在会正确广播到 num_layers 长度。

5.3 blb_stage2_rl/sequential_policy.py（新）

类关键设计
BLBStage2SequentialPolicy共享 trunk（MLP）+ 一个 MultiDiscrete action_head（size = max_step_dim × max_num_levels）。每步通过 (slot_mask, per_slot_num_levels) 屏蔽掉 padding slot 和 padding level（-inf logit），同一头服务所有 block 类型。
SequentialRolloutBuffer记录 (state, action, slot_mask, num_levels, log_prob, value, reward, done)。compute_gae(γ=0.99, λ=0.95) 跨 episode 边界正确处理 done flag。
sequential_ppo_update标准 PPO-clip，按 mini-batch 重新评估，clip_fraction 等指标返回。
step_to_mask_and_levels(spec, ...)从 BlockStepSpec 生成 (slot_mask[max_step_dim] bool, per_slot_num_levels[max_step_dim] int)。

5.4 blb_stage2_rl/sequential_runner.py（新）

函数用途
train_sequential(env, policy, train_cfg, on_episode_end, ...)独立的 horizon-N PPO 训练驱动；可单独用做 A/B 实验。修复点：只在第 0 个 episode 用 seed，后续 reset 不再每次重置 RNG。
run_sequential_via_runner(runner, train_cfg, fixed_gelu, fixed_softmax, ...)给 BLBStage2RLRunner.run 派发用：复用 runner 现有的 _build_probe_batches、_build_rescale_bridge、_estimate_baseline_metrics、resolve_blb_persistence_dir 等 setup 助手；运行 train_sequential；assemble legacy-compatible 的 noise_stage_result dict（关键字段 blb_v3_best_action_vec / blb_v3_profile / best_noise_config / limit_loss/p/s / baseline_tot_c）供下游 final-eval 使用。

其他 stage-2 路径如何被「关」

用户问「现在 blb stage2 是不是有多种方式」。答：

  • 默认 blb_v3 + sequential_rl=True（本次新设计的 horizon=59 per-block 路径）
  • opt-in blb_v3 + sequential_rl=False（旧 horizon=1 single-shot 路径；显式 --blb-v3-no-sequential-rl 启用）
  • opt-in legacy_v2（旧版 noise_rl_module_v2；显式 --stage2-rl-variant legacy_v2 启用，仅供复现历史实验）
  • 独立 GA / Greedy 搜索（不在 stage-2 RL 范畴；通过 --search-algorithm ga / greedy 走 rl_tune_genetic.py）

修复的 2 个真实 bug

  1. degree 广播：BLBStage2SequentialEnv._rebuild_schedule 之前对单元素 np.array([4]) 没扩张到 num_layers，会导致 step_schedule 拿不到 layer>0 的 degree。改用 _broadcast helper 处理 int / 单元素 / 错长度三种情况。
  2. 训练种子：train_sequential 之前每个 episode 都用相同 seed 调 env.reset(seed=...)，导致每 episode 完全相同。现在只在 ep == 0 时 seed 一次。

10. 已知限制与未来工作

  • Warmstart bias 对 K slot 不精确：apply_preferred_per_step_bias 把所有 head slot 都偏向 level = max_num_levels - 1。SF 类 slot 因 num_levels < 6 被 -inf mask 自动屏蔽 → 偏向 num_levels-1（=largest SF），正确。但 K slot（6 个 level）会偏向 K_LEVELS[5]=12 而非 K_max=13（K_LEVELS=(8,9,11,13,10,12)）。这是个温和的偏差，PPO 几个 episode 就能修正。需要严格 all-max prior 时应替换为按 (step, slot) 的条件偏置（未来工作）。
  • 每步 cfg decode 冗余：每个 step 都调用 action_vector_to_cfgs 全量解码所有 (layer, block) 后挑出当前一个，浪费 ~60× cfg 构造。可优化为「只解码当前 (layer, block)」（未来工作）。
  • candidate_store 集成尚未接入序列路径：序列 runner 用简单的 seq_env._pending_full_vec 快照 + 按 total_reward 选 best。下一步把 candidate_store 接入，让 best 选择走完整 (invalid, acc_violation, stab_violation, cost) 元组 rank（未来工作）。
  • F0 scan / candidate_store / action_mask 都仍是 legacy single-shot 假设：这些工具在 sequential 训练后依然可以读 blb_v3_best_action_vec 工作。但若要让 F0 scan 直接产出「per-step 探索建议」，需要扩展 scan 的 schedule 概念（未来工作）。
  • HeuristicStubInvoker 已删：所有路径（包括 sequential）都强制走真 ReplanSession。如果 InProcessInvoker.from_profile 失败，训练直接中止——这是去年 5 月就确立的约束。
  • 本机无 torch / numpy：本地 Python 没装 torch/numpy，所以本次所有 smoke test 都是用 stub 的，覆盖纯 Python 逻辑层。真实端到端测试需要在配好 torch + Rescale_optimizer 的服务器上跑一遍。
