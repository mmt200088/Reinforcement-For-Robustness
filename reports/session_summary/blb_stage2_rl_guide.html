2. 完整训练流程

训练入口 BLBStage2RLRunner.run() 检测到 train_cfg.sequential_rl=True（默认）会派发到 run_sequential_via_runner。整个 pipeline 7 大阶段：

阶段做了什么关键产物
0 持久化定位解析 persistent/{algo}/{model}/{dataset}/{slug}/blb_stage2/progress/blb_stage2_status.json live tail
1 应用 Stage-1把 GELU/Softmax 多项式 degree 安装到模型；清掉旧噪声模型进入 polynomial-only 状态
2 Probe + Bridge构造 MC probe batches（5 个 batch × 256 样本）；建 InProcessInvoker.from_profile() 调用 ReplanSessionrescale_bridge
3 Baseline 装载读 static_skeletons_<dataset>.json，按 (block, layer) 重建 baseline SF + active rescale slots → 校准 MaxSFsTable + 生成 baseline action vecbaseline_action_vec, max_sfs, ss_cost_stats
4 Cost / metrics baseline用 baseline action 跑几个样本：建 BaselineCostStats(total_bits, fusion, avg_k=11.78) + 评估 baseline 模型精度 / 稳定性 → 求 w_bits/w_fusion/w_k校准的 reward 权重 + hard-threshold
5 Env + Policy包装 BLBStage2SequentialEnv(base_env=...)，建 BLBStage2SequentialPolicy(state_dim=1013, head=[13×6])；warmstart bias 偏向 baseline action vecseq_env, policy, optimizer
6 Resume（如有）检测 blb_stage2_rl_checkpoint_live.pt：自动还原 policy / optimizer / start_episode / best_reward / best_action_vec；如果 ckpt 的 rl_variant ≠ blb_v3_sequential，安全跳过 load训练从断点续
7 PPO 主循环每 episode 走 59 步 per-block sequential；每步调单 graph ReplanSession → dense cost reward；末步交给 BLBStage2Env.step 跑模型 forward + 完整 hard-priority reward；每 rollout_size=60 episode 做 1 次 PPO update；每 5 次 update 打印一次进度框blb_stage2_rl_checkpoint_live.pt, blb_stage2_training_curve.{png,npz}, blb_stage2_status.json

3. Baseline 是怎么算出来的

Baseline 是 RL 训练的两个核心参考点：

  • Baseline action vec：每个 slot 在"最安全的 SF + per-block 推荐 K"下的 action index。用于 warmstart 偏置 + reward 计算中的 cost 参考。
  • BaselineCostStats：用 baseline action 跑 Rescale_optimizer + 模型 forward 得到的 total_bits / fusion_count / avg_k / loss / metric1 / metric2。

3.1 SF baseline：来自 static_skeletons

Stage-2 启动时读 Rescale_optimizer/configs/<dataset>/static_skeletons_<dataset>.json。对每个 (block, layer) 抽取：

  • Fresh SF：cut_point_sf[0].sf
  • Encode SF：propagation_deltas[*].delta（仅数值 delta，"x2" 等字面值 skip）
  • Rescale SF：cut_point_sf[r>=1].sf_post

每条 SF 写入校准后的 MaxSFsTable.by_layer_block_node，让 RL "最大档（max idx）"对应 baseline SF。不在 archive 里的 rescale slot（"off at RO baseline"）→ baseline action 取 idx 0（= 关闭该 rescale 噪声）。

3.2 Truncation K baseline：per-block 差异化（2026-05-15 修正）

之前所有 block 都默认 K=13；现在按 block 类型差异化：

BlockBaseline K含义
1 (FFN2/LN-head)13aggressive truncation：浅 block 稳健
2 (LN-tail/QKV/QK)10保守：attention 对精度敏感
3 (Softmax exp)13aggressive：迭代平方对截断不敏感
4 (Softmax·V/Wo/LN-head)10保守：output projection 对精度敏感
5 (LN-tail/Wffn1/GELU)13aggressive：GELU 多项式稳健

对 L=12 层（去掉 L0-B1，共 59 K 槽）：baseline avg_k = (4×46 + 11×59) / 59 ≈ 11.78（之前是 13.0）。RL 在 reward 上的零点也对应这个新 baseline。

为什么这样设？K 是"截断位数"，越大越激进（越便宜但越多噪声）。B2 / B4 是 attention 的两端，对精度更敏感，所以 baseline 给"温和的 K=10"。RL 仍可以选 K∈{8,9,10,11,12,13}，只是 reward 的 zero-point 落在 per-block tuned 值上。

4. 动作空间与每步决策

4.1 完整动作向量（577 维，沿用 legacy 兼容布局）

每层 48 槽 × 12 层 + 1 first_input = 577 维 MultiDiscrete

Block 1 (7 槽): F W S S R R K
Block 2 (12 槽): F F M W W M M M R R R K
Block 3 (7 槽): F S R R R R K
Block 4 (12 槽): F F M M M S S W R R R K
Block 5 (10 槽): F F M W M R R R R K

4.2 每步只决策 1 个 (layer, block)

Episode 长 59 步：

step  0: (L0, B2) + first_input fresh  → 13 维 MultiDiscrete
step  1: (L0, B3)                       → 7 维
step  2: (L0, B4)                       → 12 维
step  3: (L0, B5)                       → 10 维
step  4: (L1, B1)                       → 7 维
step  5: (L1, B2)                       → 12 维
...
step 58: (L11, B5) [terminal]           → 10 维

L0 没有 block 1（首层没有上游 FFN2），所以总步数 = 4 + 11×5 = 59。

4.3 每步 obs：static + 当前位置 + 全历史

state_dim = 1013（L=12）：

  • 静态 4 维（num_layers、attn_degree、gelu_degree、horizon）
  • 当前 step 一维 one-hot（horizon=59）
  • 当前 block 一维 one-hot（5）+ layer_idx 归一化（1）
  • 历史动作 horizon × max_step_dim（59×13=767）
  • 历史 optimizer 信号 horizon × 3（59×3=177，valid / total_bits_norm / fusion_count_norm）

4.4 共享 policy head + per-step mask

BLBStage2SequentialPolicy 共享 trunk + 单一 MultiDiscrete head（13×6 = 78 logits）。每步通过 (slot_mask, per_slot_num_levels) 把 padding slot / padding level 的 logit 屏蔽到 -inf，所以同一头服务所有 block 类型。

5. Reward 设计

5.1 Per-step（dense，每步发）

if not valid:
    reward -= invalid_penalty          # 默认 1.0
else:
    cost_ratio = total_bits / baseline_block_total_bits
    reward -= cost_shaping_coeff * (cost_ratio - 1.0)   # 默认 0.05
    # fusion_shaping_coeff 默认 0（per-block fusion 信息有限，看全局即可）

Per-step reward 故意做得比 terminal 小很多（每步 0.01-0.05 量级），让 PPO 通过 GAE-λ 主要从 terminal 学，per-step 只是"早期 invalid 警报"。

5.2 Terminal（episode 末，硬约束三层优先级）

从 BLBStage2Env.step 来：

优先级条件奖励
0 invalid有 block invalid_chain-priority0_penalty
1 accuracyacc < acc_threshold-priority1_penalty + (acc - threshold)·scale
2 stabilityloss_std > stab_threshold-priority2_penalty + (threshold - std)·scale
3 cost都通过w_bits · bits_drop + w_fusion · fusion_drop + w_k · k_drop

这是 hard-priority：cost reward 永远不会"抵消"accuracy 违例。 Best-action 选择按 (invalid_flag, acc_violation, stab_violation, normalized_cost) 元组排序。

6. preset 文件与 RL 参数说明

preset: presets/mrpc-blb-stage2-rl.conf。常用参数与建议：

参数preset 值含义 / 调参建议
--stage2-search-episodes6000总 episode 数。6000 × 59 steps = 354k env.step。算力充裕时调到 12000-20000；快速验证用 600。
--stage2-rollout-size60PPO 窗口（多少 episode 后 update 一次）。每 update 收 60 × 59 ≈ 3540 transitions。
--stage2-save-interval200checkpoint 保存间隔。MRPC 单 episode 数十秒，200 episode 间隔即每 1-2 小时一次。
--stage2-search-lr2e-4Adam 初始 LR。Sequential 的 batch 比 single-shot 大很多，LR 已经偏低；K_trials 高时可以保持。
--stage2-calibrate-baseline-samples8启动时跑 8 个随机 action 来估计 typical bits/k drop。8 通常够；想更准可调到 16。
--stage2-k-trials5每个 episode 末的 MC noise trials。5 次较稳；如果方差还大可调到 8-10。
--stage2-probe-size256每次 trial 用的样本数。256 是 MRPC 的合理 trade-off。
--blb-v3-sequential-rltrue默认 true。 设 false 回退到旧 single-shot。
--blb-v3-sequential-invalid-penalty1.0每个 invalid step 的负奖励。1.0 通常足够，invalid 在 ~10 episode 内归零。
--blb-v3-sequential-cost-shaping-coeff0.05per-step cost shaping 系数。0.05 不会主导 accuracy 信号。
--blb-v3-sequential-fusion-shaping-coeff0.0per-step fusion shaping，默认 0（用 terminal 全局 fusion）。
--blb-v3-warmstart-anchor-episodes80前 80 episode bias 策略 head 偏向 baseline，让冷启动稳定。
--stage1-accuracy-tolerance0.005Stage-1 accuracy 容差，±0.5pp。
--stage2-limit-tolerance0.005Stage-2 accuracy 容差，±0.5pp（baseline acc 下浮 0.5pp 作为硬约束）。
--stage2-stability-tolerance0.005稳定性容差，loss_std × 1.005 作为上限。

7.2 监控进度

训练期间控制台会持续输出 v2 风格的进度报告：

  1. Setup 摘要：major rule + 基线信号 + 训练超参与环境设置 boxes
  2. 训练开始：进度文件 / checkpoint / 训练曲线路径 box
  3. 第 1 个 episode：59 行逐步 trace，可以快速判断 wiring 正常
  4. 每个新高：【回合 N · 训练过程新高】 标题 + 每层 action 概览
  5. 每次 PPO 更新：PPO 窗口摘要 box（mean return / policy_loss / value_loss / entropy / clip_fraction / LR）
  6. 每 5 次 PPO 更新：BLB Stage-2 噪声 RL 进度 box（progress bar + train best + 已用时 + ETA + 完成时刻）
  7. 结束：major rule + 6 行总结

7.4 graceful stop

向 PID 发 SIGINT（Ctrl-C 一次）或在持久化目录创建 STOP_RL 文件，runner 会在下一次 PPO 边界保存 checkpoint 并安全退出（返回码 0）。

# 方式 B：在持久化目录创建 STOP_RL 文件

# 方式 C：直接发 SIGINT 给 PID
PID="$(cat 'Parting Chapter/persistent/rl/bert-base/mrpc/LATEST_PID')"
kill -INT "$PID"

# 全部清掉，从零开始

8.2 长期诊断 dashboard（2026-05-16 新加）

RL 是长期优化任务，每次结果出来或被中途叫停，都需要快速判断"哪里出问题、下一步往哪调"。诊断 recorder 在 每个 RL run 的同一持久化目录下额外落盘一份 diagnostics/ 子目录：

文件写入时机用途
diagnostics_summary.md 每 200 episode（同 checkpoint 间隔）+ 训练结束 调试入口。中文 Markdown 一页：训练进度 / Top-20 candidates 表 / first-invalid 热力 / 最近 10 次 PPO 动态 / 动作分布概览 / 自动 auto-flag 警告（学习退化 / 训练停滞 / clip 偏高 / first-invalid 集中 / policy collapse 等）
episodes.jsonl 每个 episode（append-only） 完整 per-episode 记录：reward / terminal / per_step_sum / valid_steps / invalid_steps / total_bits / fusion_count / first_invalid(layer,block,step) / early_terminated / timestamp。tail -f 友好。
ppo_updates.jsonl 每次 PPO 更新（append-only） policy_loss / value_loss / entropy / clip_fraction / n_samples / window_mean_return / window_mean_invalid / best_reward_so_far / elapsed_sec
top_candidates.jsonl 每 200 episode 重写 训练期 Top-20 best episodes（按 total_reward 降序）。每行都带人类可读的 slots 列表（label + SF / truncation_bits）+ diff_vs_baseline。
first_invalid_counts.json 每 200 episode 重写 {"L08-B3": 312, "L02-B2": 88, ...} 哪些 (layer, block) 最先 invalid。识别 stage-1 degree 是否过低 / max_sfs 表是否有 bug 的最快信号。
action_histogram.npz 每 200 episode 重写 counts: int64[num_slots=577, max_levels=6]。看哪些槽 policy 已经收敛到单一 action（policy collapse 检测）。
baseline_action_vec.json recorder 启动时（拿到 baseline 后）一次 static_skeletons baseline 的完整 slots 视图，做为 top-K 槽位 diff 的参考系。
best_action_vec.json 每次出现 episode-level 新 best 时立刻重写 训练期最优：人类可读的 slots 列表（按 SF / K 选）+ diff_vs_baseline + action_vec 兜底字段。可直接喂给 Paean/run_final_eval.sh --action-config。详见 第 8.3 节。
调试 RL 出问题时的标准流程：
  1. 先看 diagnostics_summary.md 的 "6. 自动诊断 auto-flags" 段——如果有红色警告，先按指引调。
  2. 看 "3. First-invalid 频次"：如果某一 (L, B) 占了 > 30%，说明 baseline 或 stage-1 degree 在那里设错。
  3. 看 "4. PPO 学习动态" 表：entropy 趋势下降但 best_reward 不动 → policy 锁死在差解，调大 ent_coef。
  4. 看 "5. 动作分布概览"：已收敛 slot 比例如果在第 200 episode 就 > 80%，意味着 warmstart 偏置过强。
  5. tail episodes.jsonl + jq 看任意指标的时间序列。例如 tail -n 200 episodes.jsonl | jq '.invalid_steps' | sort | uniq -c

auto-flag 触发规则一览（在 diagnostics.py 中可调）：

Flag触发条件建议调参
学习退化最近 20 ep 平均回报比前 20 ep 低 0.05+降 lr / 增 ent_coef / 减 invalid_penalty
训练停滞200+ ep 后回报变化 |Δ| < 0.05提 lr 或减 invalid_penalty
invalid 偏多最近 50 ep mean invalid > 30/59查 stage-1 degree / max_sfs 表
first-invalid 集中某 (L, B) 占 invalid 数 > 30% 且 total > 30查那个具体 layer 的 stage-1 degree
熵过低最近 3 次 PPO 平均 entropy < 0.1增 ent_coef 或 clip_range
clip_fraction 偏高最近 3 次 PPO clip_frac > 0.40降 lr
policy collapse200+ ep 后 95%+ slot 收敛，但 best_reward < 0重置或加大 ent_coef

8.3 Final eval 接口（auto + manual SF/K-based JSON）

Stage-2 RL 与 final eval 之间有两条互不冲突的路径：

8.3.1 自动路径（训练结束后自动跑）

RL 训练结束时，run_sequential_via_runner 把训练期最优写入返回 dict：

result = {
  "blb_v3_best_action_vec": [int, int, ..., int],   # 577 dim
  "blb_v3_profile": "mrpc",
  ...
}

下游 layer_importance_evaluator.run_unified_final_eval 的 _should_run_blb_action_final_eval 检测到 blb_v3_best_action_vec is not None → 自动派发到 BLBActionFinalEvaluationModule，在 validation_full 上安装真正的 BLB best 动作，跑 final_eval_repeat_n 次 MC eval。不需要手动操作。

8.3.2 手动路径：按槽位标签 + SF / K 值配置（推荐）

诊断 recorder 每出现新 best 都重写一份 diagnostics/best_action_vec.json。该文件的主要部分是 slots 列表，每个槽位带 反映模型位置的标签（不是匿名 idx），用户也可以直接复制这个文件、改里面的 SF / 截断位数。

{
  "schema_version": "blb_v3_slots_human_v1",
  "num_layers": 12,
  "profile": "mrpc",
  "source": "blb_v3_sequential_runtime_best",
  "episode": 412,
  "best_reward_so_far": 0.4521,
  "meta": { "profile": "mrpc", "fixed_label": "..." },

  "slots": [
    {
      "label": "L00.B2.F.qk_bsgs",       // ← 反映模型位置: layer 0, block 2, fresh, QK-BSGS 入口
      "layer": 0, "block": 2, "kind": "F",
      "field_name": "qk_bsgs_fresh_sf",
      "operation": "block2_qk_bsgs_fresh",
      "scaling_factor": 16,              // ← PRIMARY value，用户看这个
      "level_values": [10, 12, 14, 16],  // 这个槽位可选的所有 SF
      "max_sf": 16, "N": 14, "effective": true,
      "action_index": 5                  // 原 RL action idx，仅供 sanity check
    },
    {
      "label": "L05.B3.R.sq0",           // layer 5, block 3, rescale, softmax 第 0 个 square rescale
      "kind": "R",
      "scaling_factor": null,            // null 表示这个 rescale 在 best 里被关闭
      ...
    },
    {
      "label": "L05.B3.K",               // layer 5, block 3 输出端的 MPC↔HE 截断
      "kind": "K",
      "truncation_bits": 10,             // ← PRIMARY value，K_LEVELS={8,9,10,11,12,13}
      "level_values": [8, 9, 10, 11, 12, 13],
      ...
    },
    ...
  ],

  // 与 baseline (static_skeletons 全 max) 的逐槽差异，列出"哪些槽改了、改了多少"
  "diff_vs_baseline": [
    {"label":"L05.B3.K", "kind":"K", "baseline_truncation_bits":13, "best_truncation_bits":10, "delta":-3},
    {"label":"L02.B5.W.wffn1", "kind":"W", "baseline_scaling_factor":14, "best_scaling_factor":12, "delta":-2}
  ],

  "action_vec": [3, 4, 5, 1, ...],   // Paean 兜底字段（旧 reader 仍能读）
  "decode_rules": { ... }            // SF / K 解码规则提示
}

调用 Paean 跑 final eval：

bash Paean/run_final_eval.sh \
    --preset mrpc-final-eval-only \
    --action-config "Parting Chapter/persistent/rl/bert-base/mrpc/<slug>/blb_stage2/progress/diagnostics/best_action_vec.json"

8.3.3 手动调几个槽位的两种简写

形式 A · base + overrides（最简，强烈推荐用于人手调）：从 baseline / max 开始，只列要改的槽位。

{
  "num_layers": 12,
  "profile": "mrpc",
  "base": "max",                     // 或 "min"
  "overrides": [
    {"label": "L05.B3.K", "truncation_bits": 10},
    {"label": "L02.B5.W.wffn1", "scaling_factor": 12},
    {"label": "L08.B3.R.sq1", "scaling_factor": null}   // 关闭这个 rescale
  ]
}

形式 B · slots dict 字面值（更紧凑）：以 label 作 key，值是数字（K 槽自动识别）或 dict。

{
  "num_layers": 12,
  "profile": "mrpc",
  "base": "max",
  "slots": {
    "L05.B3.K": 10,
    "L02.B5.W.wffn1": 12,
    "L02.B5.W.wffn1.": {"scaling_factor": 12}
  }
}
SF 值不在表里时会自动 snap：如果你写 scaling_factor: 13 但该槽位实际只支持 {8, 10, 12, 14}，会自动选最接近的 14（tie-break 偏向大 SF=更稳）。snap 时会在 stderr 警告：[action_grid] N slot value(s) snapped to nearest table level。每个槽位的 level_values 字段会告诉你它的合法选项。

8.3.4 槽位标签命名约定

每个槽位的 label 严格按 L<layer>.B<block>.<kind>[.<short_field>] 命名：

kind含义value 字段label 例
FFresh ciphertext 噪声scaling_factorL00.B2.F.qk_bsgs（layer 0 block 2 QK BSGS 入口）
WWeight encode 噪声scaling_factorL02.B5.W.wffn1（layer 2 block 5 Wffn1 权重 encode）
MMask encode 噪声scaling_factorL05.B2.M.q_mask1
SScalar encode 噪声scaling_factorL08.B1.S.ln_mean（LayerNorm 均值标量 encode）
RRescale 后噪声（可关）scaling_factor 或 nullL05.B3.R.sq1（softmax 第 1 个 square rescale）
KBlock 输出端 MPC↔HE 截断 bitstruncation_bitsL05.B3.K

另外，layer 0 第一个 HE 配置在新语义下视为无损，所以 L0.B1.* 所有槽位的 effective 都是 false —— 写了也不会装。L0.first_input.F 同理。

8.3.5 旧 cartesian-sweep 接口仍可用

已有的 preset / 命令行 --range / --action-fixed 用 block<n>.<field>=... 选择器没有变：

# 在 baseline 上扫 block3 truncation 从 8 到 13
bash Paean/run_final_eval.sh \
    --preset mrpc-blb-baseline-fixed \
    --range block3.truncation=8,9,10,11,12,13 \
    --action-fixed layer2.block5.wffn1_sf=18

这些选择器接受的是 实际 SF / K 值（已经是人类友好的）。它们和新的 slots 输入互相叠加：JSON 里的 base + 命令行的 range，cartesian sweep 之间不冲突。

等价性：以上所有 manual 输入形式（formA / formB / 旧 action_vec / cartesian sweep）最终都走同一个 BLBActionFinalEvaluationModule，与 auto 路径完全等价：调真 Rescale_optimizer、同样的 MC repeat、同样的 install_verification 输出。

9. 疑难诊断 / 常见情况

第一步永远是先看 diagnostics/diagnostics_summary.md，里面的 auto-flag 段覆盖了下面绝大多数情况并给出具体建议。下表是补充的"现象 → 排查"快速索引。
现象排查
前 1 个 episode 的 step trace 显示大量 invalid正常：cold-start 时 policy 随机；warmstart 介入后 5-10 episode 内归零。如果 50 episode 后仍大量 invalid，看 diagnostics_summary.md 第 3 节 first-invalid 频次定位具体 (L, B)。
PPO clip_fraction > 0.5policy 变化过大。降 --stage2-search-lr 到 1e-4 或 5e-5；或调大 --stage2-rollout-size。auto-flag 在 clip_frac > 0.40 时会自动提醒。
entropy 一直高（> 1.5）policy 没收敛。看 ppo_updates.jsonl 的 entropy 列时间序列；可能 invalid_penalty 太低让 PPO 没紧迫感。
best_reward 停滞用 --blb-v3-sequential-cost-shaping-coeff 0.1 加大 cost 信号；或调大 ent_coef。auto-flag 在 200+ episode 停滞时会自动提醒。
resume 后训练曲线断层正常：PNG 曲线只画当前 run；合并完整曲线可以读多份 episodes.jsonl。
checkpoint load 失败 / 跳过意味着 ckpt 的 rl_variant ≠ blb_v3_sequential。如果是从旧 single-shot ckpt 继续，必须 --fresh 重启 sequential（policy 网络结构不同）。
final eval 没自动启动看 noise_stage_result 是否有 blb_v3_best_action_vec。如果 None，说明训练没产生过任何 episode（total_episodes=0 或全部 crash）。可以手动用 diagnostics/best_action_vec.json 走手动路径。
想评估 Top-N 而不是 bestdiagnostics/top_candidates.jsonl 每行一个 candidate，可以挑某行的 action_vec 自己写一个 {"action_vec": [...], "num_layers": 12} JSON 喂给 Paean。

bash llama_7B_LayerImportance.sh run rl --preset mrpc-blb-stage2-rl --fresh \
