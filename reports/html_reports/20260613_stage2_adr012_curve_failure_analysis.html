结论

这条曲线不是 replan 没生效，也不是 fusion 动作没有送进模型。Stage-2 的真实流程是：RL 动作经 fusion map 展开，再由 replan 产出真实底层配置，随后通过 bridge.apply 安装到模型，最后跑 validation probe 并进入 reward。问题出在搜索动力学：ADR-012 成功打破了上一轮 fusion=0 冻结，但新的奖励和探索结构把策略推过了安全 fusion 前沿；一旦进入高 fusion 区域，指标掉到 P1，P3-only cost reward 被清零，远离边界的 P1 又被压成近似相同的负奖励，PPO 很难把 47 步动作中哪些 block/slot 应该退回来分清楚。

全程最佳 P3 出现在 episode 20880，fusion_count=22，reward=40.805。但后续策略继续把 fusion_count 推到 30+，从 29k-30k 的 1000 窗口开始全 P1；最终 tail10000 平均 fusion_count=35.11，P3=0。

端到端动作路径

1. 策略采样
GTrXL sequential policy 对每个 Stage-2 槽位采样。ADR-012 给 fusion option 槽加 ε 下限，所以 entropy 不再掉到 0。
2. 课程与探针
curriculum 前半段限制半径，后半段全开。forced probe 每 200 集把 b2/b5 目标块追加到 option=1，但不做“降低 fusion”的反事实。
3. map 展开
fusion-count action 通过当前 MRPC fusion map 转成具体 action slots 与 fusion choices。
4. replan
env 根据动作请求 Rescale optimizer，拿到 optimizer output 后同步 qk/b2aux/b4vmask/b5aux 等绑定。
5. 模型安装
bridge.apply 安装 replan 后的真实配置，probe 评估读到的是模型实际会用的配置。
6. reward
metric/stability 先定 P1/P2/P3；只有 P3 才能拿 cost_score。P1/P2 的 external cost 被置零。

为什么会走成这样

1. ADR-012 修对了上一轮问题，但把失败模式从“零融合冻结”变成“高融合越界”

上一轮策略几乎不探索 fusion。ADR-012 的 ε 探索和探针让 fusion 出现率大幅上升：全程平均 fusion_count=24.02，最后 20k 平均 fusion_count=35.11。但安全前沿不是越高越好。当前 run 中最大 P3 fusion_count=27，而 30+ fusion 后 P3 比例快速归零。

2. Cost reward 是 P3-only，越界后“高 fusion”收益全部消失

reward 逻辑先判断 metric/stability。只要 metric 失败进入 P1，fusion/truncation 的 external cost score 就不会计入 terminal reward。因此策略在 P3 区域被鼓励增加 fusion，但跨过边界后同样的高 fusion 不再有成本收益，只剩 P1 惩罚。episode 80 的 b2 probe 是 P3、fusion=12、reward=39.56；episode 20880 的 b2 probe 还能到 P3、fusion=22、reward=40.81；到 40k 以后，fusion≈35 的 probe 和普通 episode 都是 P1。

3. 近界渐变只帮边缘 P1，救不了远离阈值的高 fusion 崩塌

按 acc threshold≈0.85828125 和 near-miss denominator 下限 0.01 估计，P1 中近界样本约 3,750，远界样本约 41,492。从 30k 后，metric1 平均已经降到 0.75 左右甚至更低，远离阈值；这些 P1 只能落到接近 -5 的 terminal reward，加上 per-step penalty 后 total_reward 稳在 -6.95 附近。

4. 探针 v2 是“追加 fusion”，不是“回退 fusion”

探针在当前策略动作基础上强制目标 block option=1。当前策略还在低/中 fusion 时，它给出有用正证据；当前策略已经高 fusion 时，它只是在坏配置上继续追加或保持 fusion，因此后期探针本身也全部 P1。它不能提供“把某个 block/type 从 1 降到 0 会恢复 P3”的反事实梯度。

5. 47 步 terminal reward 的信用分配太稀疏

一个 episode 有多个 block、多个层和 K/truncation 槽位，最终只在 terminal 才知道 P1/P3。远界 P1 被裁成相近负分后，PPO 只能知道“这一整串动作不好”，很难定位到底是 block4 过多、总 fusion 过高，还是某些层/slot 的组合越界。ε 让探索不死，但它是对称混合分布，不是针对坏高-fusion 状态的退火或修复机制。

6. 没有 rank-best/frontier 保护

训练中已经发现过可用的中等 fusion P3；但训练策略继续朝更高 fusion 区域漂移，缺少把 policy 拉回 best-P3/frontier 附近的行为克隆、elite replay、或 trust-region 约束。最终 checkpoint 的策略表现和全程 best candidate 分离。

建议的下一轮修复方向

  • 把 fusion frontier 显式纳入课程。 先把 block2+block5 的安全全开区作为目标，block4 单独限层/分层开放，不要让 all-block fusion 同时自由爬到 30+。
  • 增加回退型反事实探针。 在当前动作上强制某个 block/type 降到 option=0 或降低 fusion_count，和追加 fusion 探针成对出现。
  • P1 内部给可学习的负梯度。 对远界 P1 保留 metric deficit / block-level fusion attribution 信息，不要所有远界坏配置都只落在同一个 clipped 负分附近。
  • 用 best-P3/frontier 做策略锚定。 PPO 更新时加入 elite replay/behavior cloning 或 action prior，防止策略越过已发现的安全前沿后持续漂移。
  • 拆分 block4 风险。 固定实验已经显示 block4 全开有害而少量层可能可行；训练侧应给 block4 独立上限或独立 reward attribution。

代码定位

  • blb_stage2_rl/env.py：动作转 optimizer 请求、replan 输出同步、bridge.apply 安装、probe 与 reward 调用。
  • blb_stage2_rl/reward.py：P1/P2/P3 gate、near-miss 渐变、P3-only external cost。
  • blb_stage2_rl/fusion_cost.py：fusion/truncation 分量归一与 cost_rank。
  • blb_stage2_rl/fusion_curriculum.py：课程 ramp 与 forced probe 调度。
  • blb_stage2_rl/parallel_runner.py：多卡 episode 收集、forced probe 动作覆盖与确定性顺序回收。
  • blb_stage2_rl/sequential_policy.py：ADR-012 ε 混合分布。

一句话版本：这轮已经证明“能探索 fusion”，但探索没有安全边界和回退信号；reward 只在 P3 给成本收益，所以策略中期找到好 P3 后继续加 fusion，越界后进入大量高-fusion P1，最终曲线表现为 reward 崩塌。
